> **Update after 1.1.0 (unreleased follow-up, 2026-10-22):** the rest of the backlog is done except table captions, see [Follow-up after 1.1.0](#follow-up-after-110) at the end.
>
> **Update after 1.0.0 (post-1.0 follow-up, for 1.0.1, 2026-10-22):** backlog items 1, 2 (target sizes), 3, 8 and most of the M6.4 editor items are now fixed, see [Follow-up for 1.0.1](#follow-up-for-101) at the end. The tables below keep the state as audited for 1.0.

Date: 2026-10-22. Auditor: Accessibility Auditor. Standard: WCAG 2.2 Level AA. Code changed in `apps/web` (small fixes, listed below); nothing committed.

## Scope and method

Screens: **Account** (`/account`), **Admin Users** (`/admin/users`, with the reset-link, delete, disable and enable dialogs), **Admin Backups** (`/admin/backups`, with the download dialog), **Reset** (`/reset`, `/reset#<token>`), **Trash** (`/c/:id/trash`, with the campaign sidebar around it). Both themes (light and dark through `prefers-color-scheme`), at 1280 px, 390 px and 320 px wide (320 px is the 400 % zoom reflow check).

Setup: the bundled server (unchanged `apps/server/dist`) on **port 3322** with a fresh `DATA_DIR` in the session scratchpad; the current web sources built to a separate folder (`WEB_DIST_DIR`), so the shared `dist/` was not touched. Seed: admin "Jan", a second user "Wren Player" (through an invite), a campaign with pages, two of them in the trash (one with a subpage), an API token, a backup. Real data was not used. System Chrome through Playwright (not the full `pnpm e2e`). The server was stopped at the end.

Checks:
1. axe-core 4.7, all rules including `best-practice`, WCAG 2.2 `target-size` and the experimental `label-content-name-mismatch`, with violations and "needs review" results, on every screen x theme x width (24 runs after the fixes, plus the dialogs open).
2. Keyboard: a full Tab pass of every screen in both themes (stop count, accessible name, focus ring, size, visibility), then every flow done with the keyboard only: skip link; form errors; dialog open, focus trap, Esc, focus return; success and failure paths of each action; what holds focus after each change.
3. Contrast measured by script: text (axe), form-field borders (1.4.11) against the surface behind them, the focus ring against the page and header, in both themes.
4. Reflow at 320 px (no horizontal scroll, axe clean), heading structure, page titles, live regions.
5. The M6.4 "Backlog to G1.2" items, one by one (table below).

**Not done (stated plainly):** no real screen reader (NVDA, JAWS, VoiceOver) was run, so announcements are judged from roles, names, live regions and focus targets, not heard. No voice-control, forced-colors, reduced-motion or real-device runs. No pointer-size test on a real phone (emulation only, as in M6.1). A clean axe run is not a conformance claim. The Trash screen's "3 days left" accent style was checked by computing its colours, not by seeding an aged item.

## What works well (kept as is)

- Every form field has a visible `<label>`; errors are in a `role="alert"` region, the field gets `aria-invalid` and `aria-describedby`, and focus moves to the first bad field (Account name and password, Reset, the step-up dialog). Tested for empty, weak, mismatched and wrong-current input.
- The shared step-up dialog (reset link, delete, disable, enable admin, backup download): `role="dialog"`, `aria-modal`, labelled and described, focus lands on the password field, Tab and Shift+Tab stay inside, the page behind is `inert`, Esc closes it and focus returns to the button that opened it, "Done" and Esc work from the result view, axe is clean in the dialog in both themes.
- Action buttons carry names with the person (`Reset link for Wren Player`) and the visible text is contained in the name (2.5.3). Rules that block an action (own account, last admin) use `aria-disabled` plus a visible reason tied by `aria-describedby`, so keyboard users can still reach and read them.
- Results are announced: `role="status"` strings for done actions ("Wren Player is disabled..."), and after an action the focus is on a sensible element (the Enable button after Disable; the same button after Restore).
- Reset: the token leaves the address bar at once, the heading or first field gets focus for each state (invalid link, ready, error), the form reads in the right order and has a real `<h1>`.
- Trash: a labelled list ("Deleted pages"), row buttons named per page (`Restore: Rumours`), a hidden separator in the date text for screen readers, focus to the heading after a purge, a status line with an "Open page" link after a restore. The native `confirm()` for permanent delete is accessible.
- Headings are in order on all screens (h1, then h2/h3); page titles are unique and descriptive; tables have captions and `scope`; both layouts (table above `md`, cards below) exist as separate lists, no duplicate announcements.
- Focus ring: 2 px accent, 3.4:1 (light) and 9.0:1 (dark) against the page, present on every one of the 18 to 30 tab stops per screen; no stop is hidden or off-screen; no keyboard trap.
- Reflow: no horizontal scroll at 320 px on any screen; the admin tables become cards.
- Text contrast: axe `color-contrast` has no violation in either theme (admin badges, muted help text, the disabled-state reasons, error text, the dark-mode accent button).

## Remaining backlog (not fixed; larger or outside these screens)

1. **No focus or announcement on route change** (app-wide, 2.4.3 / 4.1.3, Moderate): after a navigation, or after a successful reset sends the user to `/campaigns`, focus stays on `<body>`; a screen-reader user hears nothing about the new page. Needs one shell-level decision (move focus to the `<h1>` or `<main>` after `NavigationEnd`, plus a polite title announcement).
2. **Small targets at desktop width** (2.5.8 passes by the spacing exception, Minor): sidebar "← All campaigns" (94 x 16 px), "+ New" (57 x 20 px), header links and buttons 28 to 32 px high, admin row buttons 26 px high. All at least 24 px or spaced; below the 44 px used on touch.
3. **Mobile campaign drawer**: `<aside role="dialog">` is not an allowed role for `aside` (axe "needs review"; works, Low). Use a `div`.
4. **Native `confirm()`** for token revoke and Trash permanent delete: accessible, but inconsistent with the step-up dialog elsewhere and not styled for the dark theme. Product decision.
5. **Trash title** is "Trash" while the other new screens end in "— Critical Notes" (all campaign pages share this; not a failure).
6. Not tested, to do in G1.4 or with a person: real NVDA, VoiceOver and TalkBack runs of the five flows; forced-colors mode; `prefers-reduced-motion`; 200 % text-spacing override; the aged-item style on Trash (3 days left or fewer).
7. The M6.4 items for the editor and the content views (table above) still need their own pass.

8. **Field borders still on `border-line` (1.4.11, Serious outside the audited screens):** `campaign/settings.ts`, `campaign/views/npcs.ts`, `campaign/npc-statblock.ts`, `homebrew/entries-editor.ts`, `homebrew/forms/table-rows.ts`, the command palette, `reference-list`, and the editor atom views. Suggested sweep: give each of these inputs, selects and textareas the `.cn-input` class (or `border-control` where the width must stay custom), then re-run axe and the border-contrast script. Plain buttons with text labels do not need the stronger border.
